{{- if eq (toString .Values.config.trustProxy) "true" }}

  WARNING: "true" is the weak dialect. Fastify honours it, but better-auth
  attributes a forwarded header only from RANGES — with "true" it resolves
  nothing once a proxy has appended itself, so the auth limits (counted in
  Postgres, across replicas) apply to everybody together instead of per client.
  Set the pod network's CIDR instead.
{{- end }}
{{- else }}not trusted — the per-IP rate limits use the socket address.

  Right if the api is reached directly. If ANYTHING proxies to it — an
  IngressRoute, a service mesh, a load balancer onto the Services — every
  request arrives from that proxy and all callers share one rate-limit bucket.
  Set config.trustProxy to the pod network's CIDR if so.
{{- end }}

  clock   EXTERNAL (RUN_CRONJOB=false). Nothing recurs until something posts:

            curl -fsS -X POST https://<host>/api/internal/tick \
              -H "Authorization: Bearer $CRON_TRIGGER_SECRET"

          It runs the whole tick — claims what became due, enqueues and drains
          it — answering within 25s; `"drained": false` means ping again to
          resume. Safe to call as often as you like — passes are claimed per
          occurrence, so repeats inside one bucket enqueue nothing.

{{- if .Values.config.allowPrivateClusterTargets }}

Private cluster targets are ALLOWED: accounts can point Indexterity at
loopback and RFC1918 addresses. Correct for a self-hosted install whose
database is on this network; unsafe if strangers can sign up.
{{- end }}
{{- if .Values.config.allowInsecureClusterTls }}

TLS is NOT required on cluster connections: Indexterity will dial a MongoDB in
plaintext, and will accept one whose certificate it cannot verify. Credentials
and every collection name cross the network in the clear. Correct only for a
database on a trusted network that serves no certificate.
{{- end }}
